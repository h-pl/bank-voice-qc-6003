## 3. 明确差异与处理建议

### D01｜提醒方式与飞书现版不同：需求版本冲突，高优先级

**飞书要求：**3.5／3.6 提供“提醒方式：站内通知、通话中提醒”；4.2 的实时提醒动作要求策略配置了通话中提醒，并向实时通话坐席执行。

**当前实现：**策略表单只有通知接收人、重复提醒、处理流程；保存强制 `method: 'notification'`，实时与事后检测统一进入通知中心。是否通知坐席由“当前坐席”接收人选择决定。

**本地 PRD：**第 97 行明确采用通知中心统一入口，并写明策略不配置提醒方式或通话中提醒开关。当前实现符合本地这一条，与飞书 229 相反。

**影响：**研发与验收使用不同 PRD 时，会对实时坐席提醒的配置入口、发送条件和接收对象作出不同判断。

**建议：**先统一唯一需求口径。按飞书 229 验收时，应补提醒方式及实时坐席路径；若继续采用当前产品方案，应同步修订飞书 3.5、3.6、4.2。此项先解决版本冲突，再安排实现。

**证据：**`components/strategy.tsx:132` 起的策略表单；`lib/configuration.ts:69`；`lib/call-alerts.ts:98` 起的通知处理。飞书锚点：[3.6](https://acnc6zeentra.feishu.cn/docx/ZJP3dDgxpoV4PVxbkJfc8h5fnAf#doxcnkJf3LdDW4dgUtqVoewn2uc)。

### D02｜规则换绑影响在办问题等级：实现偏差，高优先级

**飞书要求：**3.6 明确在办问题沿用已记录的策略关联；4.2 根据有效命中记录所关联策略的当前等级聚合。规则换绑与原策略等级调整是两种操作。

**当前实现：**`reconcileAlerts` 根据命中的 `ruleId` 查该规则现在关联的策略，而非命中保留的 `policy.id`。

**实测：**同一在办隐私问题最初命中高风险策略；从原策略移除规则后，告警立即变中风险；将规则绑定新低风险策略后变低风险。原命中仍写“合规安全预警”，新证据和新问题均未增加。

**影响：**调整后续规则归属时，旧问题等级及可能的处置期限也被改动；显示的原命中策略与当前等级来源分离。

**建议：**在办问题按有效命中保存的策略标识读取该策略当前等级；新问题使用规则现关联策略。策略删除后的历史关联等级取值须一并明确，避免退回默认等级的隐式变化。

**证据：**`lib/call-alerts.ts:58`；[复现脚本](./audit/配置逻辑复现-20261102.mjs)及[结果](./audit/配置逻辑复现-20261102.json)。

### D03｜语言表达资源与规则特征联动：代码内部风险，退出明确 PRD 差异

**PRD 要求：**3.1／3.4 中资源提供表达特征及说明，规则选择对应检测特征；3.7 要求引用及资源内容校验。

**当前实现：**表达资源允许自由新增、删除、改名；规则特征固定硬编码为静默、抢话、语速过快、语速过慢。保存资源时的引用校验使用这个固定数组，未读取实际资源条目。

**实测：**将语言表达资源保存为仅一条“静默”，保存成功；规则仍显示四项可用特征，四项原有效条件仍保留。新加自定义资源特征也不会成为可选规则特征。

**影响：**资源内容与规则可配置项出现两套事实，用户无法通过资源维护判断哪些检测特征有效。

**分类更正：**飞书明确允许资源明细增删改，未明确规定删除表达明细时如何处理规则特征引用。固定四项且只编辑说明是额外设计方案，尚未获用户确认；资源页面本轮保持现状。本条仅保留实测联动风险，不据此将资源增删入口判为违反 PRD。

**证据：**`lib/configuration-schema.ts:5`、`lib/configuration.ts:47`、`components/structured-resource.tsx:76`；复现结果见 D02 同目录。

### D04｜适用业务：用户确认全量检测，撤回展示建议

**飞书要求：**3.1 的业务分类由后台提供，客户侧只读展示适用业务；全部业务表示预设适用范围。

**当前实现：**规则数据具有 `businesses`，启动自动检测时按业务过滤；两页及规则详情未展示适用业务。

**用户确认：**全量检测，不需要适用业务范围逻辑，不增加展示字段。

**处理方向：**飞书 PRD 删除客户侧适用业务范围及展示要求，明确全量检测。源码已有业务过滤记录为后续按新口径检查的遗留项；本轮仅更新梳理和约定，未调整执行代码。

**证据：**`lib/configuration.ts:9`、`lib/configuration-schema.ts:51`、`components/strategy.tsx:58` 起的详情区域。

### D05｜累计窗口：用户确认保留手动输入秒数

**飞书与本地要求：**3.5 可选整通通话、最近 1 分钟、最近 5 分钟、自定义秒数。

**当前实现：**声纹与通用条件编辑器均使用秒数输入框，0 表示整通，60／300 可表达对应窗口。

**用户确认：**保持手动输入秒数，不增加预设选项。

**处理方向：**飞书 PRD 将预设选择描述改为秒数输入，0 表示整通通话，保留现有参数校验与检测契约。

**证据：**`components/detection-conditions-editor.tsx:17`、`components/voice-conditions-editor.tsx:76` 附近。
