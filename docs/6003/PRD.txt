背景与本期范围
一通电话一条告警：多个问题归入同一通话告警，问题独立流转；单个问题办结只更新聚合进度，全部问题办结后关闭告警。本产品将三条流程中的办理责任、返回路径和结果串联起来，减少重复录入和状态歧义。
分期与依赖
首期 P0 完成三条默认办理流程及证据、权限、通知、期限。P1 完成指标启停、资源编辑、策略关联与特殊流程选择、实时提醒。P2 提供质量报表。功能编号与分期以功能清单为准。P0 依赖可用的组织身份、录音、检测结果、系统默认预警设置和初始业务依据；接入要求见 3.3。各阶段按第 7 章验收，依赖顺序见 8.4。

配置链路与职责
对象关系：一个指标对应一个资源对象，指标规则保存检测条件，关联资源提供业务内容，共同形成唯一的检测规则。资源中的多条明细均属于该资源，专业性的 SOP 与业务知识放在同一资源的两个分区。建设顺序：后台提供一一对应的指标、资源和规则 → 主管编辑资源内容与指标规则的检测条件 → 在预警策略中选择适用规则、等级、提醒角色和流程 → 开启指标 → 执行检测。页面归属：指标页提供开启、关闭及编辑规则，展示关联资源、检测条件和策略；资源页只允许查看、编辑；策略页集中维护规则关联和预警后的动作。规则固定一对一形成，检测条件在指标规则内编辑，不提供新增或删除规则入口。业务分类：指标定义、适用业务及资源对应关系由后台提供。客户侧只读展示，全部业务表示预设适用范围。所有接入通话自动、全量进入检测，系统执行已开启且适用的指标规则。告警队列字段在风险预警页的“列表展示设置”维护。主管编辑，质检员只读，保存后生效。对应约束：一个指标、一份资源、一条规则固定对应；资源内容可有多条记录。多条规则可共用一条策略，每条规则最多关联一条生效策略。

指标定义与检测输出（F09）
分类与职责
指标口径：标准材料第 6.2、6.3 节共 16 项评估指标（6 项 AI 核心技术能力、10 项业务能力）。产品将其中 12 项作为检测指标，覆盖率、时效性、数据展示及风险上报与干预分别落实到自动检测统计、列表展示和预警配置；12 类检测指标详见 3.4，自动检测与列表展示要求见 3.3.3，预警策略见 3.6。标准目录：YD/T 4394.6—2023（通信行业标准）对应关系：12 类指标各对应一个资源对象，并形成 12 条规则。专业性资源内包含 SOP 与业务知识分区，多项检查内容归入同一条规则。语音识别、文本纠错输出处理结果，其余 10 类指标形成风险判断。P0 接入已提供的检测结果与依据，P1 按本节及 3 完成能力接入和配置增强。客户可维护的字段、资源及预警条件以 第 3 章配置依赖 为唯一配置定义。本节只说明检测输入、结果、证据与能力边界，不另外定义一套配置表。
检测结果与证据要求
序号指标输入及处理要求输出与边界1声纹识别授权注册语音、待测原音与预期坐席身份；角色分离不能替代身份比对。输出身份一致性与比对片段；异常区分身份不匹配、未注册声纹、无法确认身份。缺注册与无法确认不直接认定违规；注册和真实比对能力单独评审。2语音识别录音或实时音频、声道 / 说话人及识别热词；保留增量与最终文本。输出角色、时间范围和转写；角色不确定及转写失败明确标记，不作为“未发现风险”。接入方式与实时音频接口待联调。3关键词检出按关键词与同义词检出实际出现内容。输出原词、原话、角色和时间；只有有效检出事件进入预警判断，不做“未出现”预警。4文本纠错根据纠错词库形成修订，保留原文、修订文和差异。明确下游使用的原文或修订文；金额、账号、日期、利率等关键实体疑点需回听核对，不覆盖原始证据。5情绪识别结合角色音频与上下文输出已交付标签中的情绪。保留情绪区间及回听证据；低质量输入标记无法判断，客户不满不自动等于坐席违规。6意图识别按当前有效的意图定义识别诉求，并保留多意图及诉求变化。输出意图、支持原话及未知结果；未知不强制归入已知类别，也不默认预警。7服务礼仪按礼仪规范判断必说要素、允许表达与例外。缺失结果提供应完成要素和已检查范围；结束语须在结束后判断，突然挂机等按例外处理。8专业性使用通话发生时适用的业务知识和 SOP 核对事实与步骤。输出疑似错答 / 缺步骤及实际采用的业务依据；资料不足或冲突时转人工核对，不生成确定结论。9隐私性根据隐私规则、信息类型、禁止行为与对话语境判断。输出脱敏证据、适用依据和例外；客户主动提供本人信息不自动算坐席泄露，检测与展示脱敏分别验收。10禁用词根据禁用词库、类别与例外识别有效命中。保留原话及例外判断；可复用关键词证据，同一业务问题不因关联多个指标重复统计。11消极情感根据服务态度规范及连续对话判断敷衍、推诿等表现。保留具体服务行为和上下文；客户不满与坐席服务态度分别判断，不能仅凭负面情绪定责。12语言表达依靠角色音频、时间对齐与语速计算识别静默、抢话、语速过快 / 过慢；保留语速数值及计算依据。输出区间、角色、数值、单位及计算范围；正常附和、系统保持等须保留场景依据，音频或角色不可靠时标记无法判断。
执行状态、平台统计与追溯
执行状态与业务判断分别保存。执行状态为待执行、执行中、成功、失败；适用的风险检测结果为命中、未命中、无法判断、不适用。语音识别和文本纠错保存各自处理结果，不强套违规命中结构。失败不得填未命中，不适用须说明依据；通话中的结果只代表已检查范围。结果关联通话、指标、角色、范围、业务依据及原音 / 文本证据；规则命中保存触发条件、当时策略或默认设置的等级、提醒角色和流程选择；告警保存当前动态等级、历史最高等级及等级变更记录。每通通话展示一份当前检测结果，保留检测状态、时间、结果和证据；自动结果与人工结论分别保存。失败重试由系统记录，已生成问题的原始证据继续保留。检测时采用的参数和实际依据随业务结果保留；资源更新后，已产生结果的证据继续可查。
序号平台设置统计或行为要求1覆盖率所有接入通话自动、全量进入检测。以接入清单中去重的全部应处理通话为分母，区分接入、处理中、完成、部分失败、失败和漏跑；重试不增加通话数，缺源清单时不可计算覆盖率。2时效性系统记录实时与事后检测的执行时间及状态。计时起止点在项目接入契约中统一，不由各策略自行解释；记录阶段时间、失败及未完成状态，供排查检测异常。3数据展示告警队列在“列表展示设置”中选择坐席、班组、业务、通话时长和检测状态。列、筛选及导出字段受用户权限约束。报表口径统一见 5.5；无数据、失败与数值 0 分开显示。
证据呈现顺序为发现内容、原音原话、业务依据、当前责任。缺失类结果展示已检查范围；专业性补充实际业务依据；声学结果补区间与数值；敏感证据按授权脱敏。通话中与事后复检通过同一风险关联信息追溯，不重复创建待办。直接查看当次检测采用的依据及原始证据。
能力评测与交付边界
接入方提供录音与角色信息、业务资源、授权声纹注册资料、应处理清单和计时口径。检测方说明能力范围、输出、失败码及服务标识。业务与测试确认样本、标注和质量门槛。身份比对、转写、纠错及分类检测分别评测误识别、遗漏、误改和证据定位；专业性核对业务事实与专家一致性，隐私检测与脱敏分开验证。覆盖率、时效性、展示及风险处置按对应检测和功能结果验收。样本不足、零分母或执行失败不得算通过，也不统一套用未经确认的准确率。
指标、规则与资源字段字典
字典按 12 类指标列出唯一对应的资源及判断配置。业务内容在资源编辑中维护；检测特征、角色、阶段、次数和持续时长在对应指标规则内编辑，指标另设开启或关闭操作。覆盖率与检测耗时由系统统计；告警队列展示字段在列表展示设置维护。

规则：由指标与资源配置形成
规则身份：系统为每个指标及对应资源形成一条固定规则。规则名称统一为“指标名称＋规则”，资源列表、策略关联、预警命中均展示同一条规则的名称。规则展示关联指标、资源入口、当前检测条件、指标开关及关联策略，并提供编辑规则入口。配置归属：检测特征、检测角色、阶段范围、累计次数、统计窗口和持续时长在指标规则编辑中填写；策略只配置规则关联、预警等级、通知接收人、重复提醒间隔和处理流程。特征匹配：声纹异常、情绪、意图和表达特征在对应指标规则内选择；匹配任一已选特征后再按该规则的次数或持续条件判断。意图来自当前资源内容，失效选项就近报错，隐藏条件不参与执行。检测范围：全程、开场、服务中、结束按指标能力开放。开场从开始计算，结束从终点倒数，服务中为开始后 N 秒至结束前 M 秒；短通话没有有效中段时不命中，依赖终点的范围在结束后判断。次数与持续：单次命中、累计 N 次或持续 N 秒按能力开放；累计窗口可选整通通话、最近 1 分钟、最近 5 分钟或自定义秒数。关键词每次有效出现计一次，其他指标按检测服务事件去重；只在同通话、同规则内累计。持续时长按同角色同连续状态计算，不能拼接角色或把次数换算成时长。参数校验：次数、时长为正整数，服务中起止偏移允许为 0。不支持的角色、阶段和条件不可选择；语速阈值使用一致计算口径与单位，数值上限按接入能力确认。启停：指标开启后执行形成的规则；关闭后停止该指标后续检测。已产生预警继续处理；重新开启用于后续检测，不自动补跑已完成通话。
预警策略：规则关联、等级、提醒与流程
序号字段可配置项填写规则1策略名称业务名称必填，用于识别共用策略2适用规则支持预警的规则，可多选在策略页维护关联；多选表示共用配置。每条规则最多关联一条生效策略，冲突时展示占用策略并阻止保存3预警等级高、中、低必填；用于命中标记、问题办理时限和通话告警等级聚合4通知接收人所属主管、质检员、当前坐席按组织范围确定实际接收人；选择质检员时通知组织范围内具有质检员角色的人员；选择当前坐席才向该通话坐席发送预警通知。通知接收人与流程责任人分别配置5重复提醒间隔每通话仅一次、1 分钟、5 分钟、自定义秒数按通话、策略、接收对象去重；首次立即提醒，再次命中且达到间隔时再次提醒；每通话仅一次只发送首次提醒。自定义为 1–86400 的整数秒；每个新问题的办理待办单独创建6处理流程默认流程、指定特殊流程默认选默认流程；特殊流程从系统已配置流程中选择，必须可执行且责任路由完整7特殊流程已配置流程的名称与入口仅选择特殊流程时必填；展示首节点、责任角色和退回 / 结束路径。首节点为质检员时，由系统在组织内按未办结复核工单数量优先分配，数量相同时按人员标识稳定选择；新问题自动分流，已有工单保持原负责人。配置页显示“质检员 · 系统自动分流”，不固定展示个人姓名。默认流程在页面显示为“优先质检主管”。切回默认流程后不执行隐藏选项
通知入口与时机：预警消息统一进入通知中心和提醒列表，策略不配置提醒方式或通话中提醒开关。实时检测在通话中产生有效命中后立即通知所选接收人，事后检测产生有效命中后发送通知；同一通话的重复命中按策略间隔去重。流程独立创建待办并通知办理责任人，预警接收人和重复提醒设置只控制预警消息。关联入口：主管在预警策略的适用规则字段多选规则并保存。指标详情只读展示所关联策略，并提供查看策略入口。解除关联或更换策略后，后续命中使用新的关联结果；历史命中记录保留。共用方式：各指标规则按自己的检测条件独立判断，命中后使用共用策略的等级、提醒角色和流程。单规则的累计次数与持续时长继续有效；本期不按多个规则命中的数量组合触发，也不因三个高风险命中自动增加推送或切换流程。默认路径：规则未关联策略时，使用系统默认预警等级、默认提醒角色和第 4.1 节默认流程。关联策略选择默认流程时，使用策略的等级和提醒角色，流程仍按第 4.1 节执行。默认参数由系统统一提供，在检测启用前校验完整。特殊路径：关联策略指定特殊流程时，当前问题进入选定流程，按该流程的首节点和责任路由生成待办。只选择已有可执行流程，本期不新增流程绘制器；具体特殊流程节点及角色由业务确认后配置。边界与兜底：提醒负责发送消息，流程负责派任务和交接；通知失败可重试，任务创建失败保留预警并交主管处理。特殊流程失效或无可用接收人时退回默认流程，同时保存原因并通知主管。同通话多问题：不同问题各走自己的流程，集中归入同一通话告警。一个问题已有办理流程时，重复命中只追加证据与命中记录；新增命中携带其他流程要求时提示主管核查，沿用当前流程，避免重复派单。变更生效：策略的提醒角色和流程更新只用于后续新问题；在办问题继续原流程。等级变更按第 4.2 节重算未关闭告警，保留原命中等级和变化记录。已关闭告警保持原记录。

配置保存、生效与权限
权限与操作：主管可开启或关闭指标、查看与编辑资源、保存预警策略；质检员只读并可提建议。资源和规则没有单独启停，规则随指标开关执行。校验与反馈：保存前检查必填、数值、枚举、一一对应关系、资源内容、检测能力、规则占用、流程可执行性、角色范围及并发冲突。失败保留输入；取消放弃本次修改并返回原页面；成功同步关联展示。更新生效：资源校验保存后直接更新，并用于后续新启动的检测；已开始的检测沿用启动时的内容。保留实际采用的条件和依据，已产生的命中证据及业务处理记录继续可查。指标关闭：停止后续检测，不删除既有命中、不撤销已经生成的预警与待办；在办问题继续走完原流程。重新开启前校验资源内容有效。策略生效：关联、提醒和流程变化用于后续新问题；等级变更按第 4.2 节处理。在办任务不因配置更新被撤销或重新创建。操作记录保存修改人、时间和具体变更内容。

风险预警与提醒（F02、F03）
唯一记录：同一组织内一通电话最多一条告警（CallAlert），使用稳定通话标识关联。首次有效规则命中创建；后续命中与重试更新原告警，重复回调不增加告警或问题数量。问题与命中：告警下保留多个独立问题（Finding），每个问题可关联多个指标、规则、策略和证据。同一业务问题的重复命中追加证据；不同问题分别登记，不能按规则条数直接生成重复问题。人工发现：通话已有告警时，后续人工发现归入同一告警并参与办理进度；纯人工发现沿用抽检与问题记录，未出现有效规则命中时不创建自动告警。之后出现自动告警时关联已有问题及历史。等级计算：当前告警等级取“未办结且未确认误报 / 撤销的问题”所关联有效命中的现行策略等级或默认预警等级中的最高等级（高 > 中 > 低）。待核实、待回应、申诉中及整改中的问题均参加；已办结或排除的问题退出。动态重算：新增有效命中、问题办结、误报确认、申诉撤销、问题重开及策略等级调整时，重算未关闭告警等级。指标关闭只影响后续检测，已有命中及其办理责任继续保留。无可聚合等级：没有未办结有效自动问题参加聚合时，当前等级显示“—”，并说明“待人工问题处理”或“等待检测完成”；保持实际办理状态。人工问题不虚构策略等级。等级留痕：保留各命中当时等级、告警当前等级、历史最高等级、关闭前等级；每次变化记录前后等级、关联策略 / 问题、原因和生效时间。策略等级调整仅改变当前风险聚合，历史命中事实和正式结论保持原记录。独立办理：主管逐问题确认、检查和分发；坐席逐问题回应、申诉或整改。各问题保留独立责任人、阶段、期限与材料，任一问题的动作只更新本问题及告警汇总。关闭条件：通话已结束，应检范围已完成（自动检测完成或人工补检经主管确认），且所有关联问题及其申诉 / 整改均已办结，系统才关闭告警。检测失败或仍在执行时显示待处理原因，分发成功只结束该问题的主管处置阶段。关闭结果：全部自动问题误报 / 撤销且无成立的人工问题时记为“全部排除”；有成立问题并完成整改时记为“处理完成”。逐问题保留实际结果，混合结果不标为整通误报。关闭后新增：有效新问题进入原告警并重开，沿用告警编号、保留各次关闭与重开记录。重复消息只补齐同一记录；已办结问题的新证据交主管确认是否重开，不自动覆盖正式结论。状态汇总：待处理＝尚无问题开始有效处理；处理中＝已有处理且关闭条件未满足；已关闭＝满足关闭条件。详情同时展示待初审、核实中、待回应、申诉、整改、已办结的问题数量与责任人。

联调顺序与上线条件
交付顺序：接入准备 → P0 基础 → 三条流程闭环 → P1 增强 → P2 扩展。
序号阶段启动条件完成出口1接入准备组织权限、录音 / 检测接口、初始业务依据和样本可用。输入、字段、失败码及期限口径可联调。2P0 基础接入条件齐备。证据读取、预警分流、身份与责任路由可用。3P0 闭环基础能力可用。三条流程及异常路径按 A01–A08、A13–A14 验收。4P1 增强实时检测能力与配置接口可用。提醒、策略与资源验收通过，回归 P0。5P2 扩展真实办理数据与统计口径齐备。质量报表对账、明细下钻和导出验收通过。
每期上线前完成所属功能的授权、证据留存、时限、监控、备份恢复和容量验证；外部依赖未就绪的功能单独记录状态。
