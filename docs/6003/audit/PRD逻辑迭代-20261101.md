## 修复结果

| PRD 依据 | 复现问题 | 现在的行为 |
| --- | --- | --- |
| 4.2、4.2.1 | 实时提醒把尚未有效处理的告警改成处理中 | 提醒、已读保持待处理；正式派单或业务处理后再更新阶段 |
| 4.2、5.1 | 人工问题后续命中自动规则时生成第二个问题，或已有问题带命中记录却缺少告警 | 按业务问题标识合并命中，创建唯一通话告警；原人工来源、检查任务、责任人与期限保留 |
| 3.3、5.1 | 最新批次统计只读取自动来源问题，漏掉人工问题关联的实际自动命中 | 读取批次命中记录；人工发现仍单独计数，保持自动候选误报统计的原有分母 |
| 3.5 | 通话长度等于服务中前后偏移之和时，零长度中段仍可触发 | 中段必须具有正长度，短通话和空中段不触发 |
| 3.3、3.5 | 零次、负数、非整数或无效次数、越界时间及无效持续时长可生成告警 | 校验有效次数、通话内发生位置及当前启用的持续时长；错误请求保留原状态，隐藏时长字段不参与判断 |
| 3.1、3.3 | 旧数据若给语音识别或文本纠错带入条件，可通过检测回调生成风险 | 在回调入口校验指标能力，处理型指标只保留处理职责 |
| 4.2 | 已办结问题在重检中收到相同证据，也会产生主管新证据确认任务 | 继续保存每次批次命中；相同规则、特征、证据、观察值和业务依据只留记录，真实新增证据交主管确认 |
| 3.7 | 专业性指标重新开启时只校验 SOP，遗漏业务知识 | 同时校验 SOP 与业务知识；任一区域无效则保持关闭 |
| 3.3.3、3.7 | 任务设置保存可覆盖固定对象编号和类型，导致后续无法定位配置 | 仅写入可编辑字段，保留固定编号、类型及系统维护的修订号 |

## 浏览器实测

- 主管从已关闭告警进入“处理新证据”，填写依据并确认重开：原告警变为处理中，原问题回到初审，历史结论保留，待确认标记清除。
